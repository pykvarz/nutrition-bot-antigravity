# ACCEPTANCE — что считаем готовым

Каждый пункт закрывается только при наличии evidence:
лог, вывод теста, скриншот, curl-ответ или diff.
«Работает» без evidence не считается.

## A. Архитектурные инварианты

Проверяется grep'ом и чтением кода. Не требует запуска.

- [ ] **A1.** В коде нет `MemoryStorage` aiogram и нет глобальных
  переменных, хранящих state между запросами.
  Evidence: `grep -rn "MemoryStorage\|^state =\|^_state =" bot/`

- [ ] **A2.** Все вызовы gspread обёрнуты в `asyncio.to_thread`.
  Evidence: `grep -rn "sheets\.\|gspread\." bot/ | grep -v "to_thread"`
  → пусто.

- [ ] **A3.** Нет `date.today()`, `datetime.now().date()` вне
  `calculate_food_date`.
  Evidence: `grep -rn "date.today()" bot/` → только в utils/dates.py.

- [ ] **A4.** Handlers не импортируют `gspread` и не вызывают Sheets
  напрямую.
  Evidence: `grep -rn "gspread" bot/handlers/` → пусто.

- [ ] **A5.** Handlers не считают КБЖУ.
  Evidence: `grep -rn "calories +\|protein +\|\* portion" bot/handlers/`
  → пусто.

- [ ] **A6.** GeminiService не импортирует SheetsService.
  Evidence: `grep -n "sheets" bot/services/gemini_service.py` → пусто.

- [ ] **A7.** Нет `asyncio.create_task` в webhook-обработке после
  отправки response.
  Evidence: `grep -rn "create_task" bot/`

- [ ] **A8.** Секреты не логируются.
  Evidence: `grep -rn "log.*TOKEN\|log.*KEY\|log.*SECRET" bot/` → пусто.

## B. Функциональные сценарии

Каждый проверяется вручную через реальный Telegram. Evidence: скриншот
или текст ответа бота.

### B1. Добавление еды

- [ ] Текст: «Съел 500 г курицы и 200 г чечевицы»
  → запись в «Дневник», `Структура_JSON` с двумя items,
  ответ с КБЖУ и «Сегодня: X / 1900».

- [ ] Голос: та же фраза голосом
  → тот же результат, `Источник=voice`.

- [ ] Фото еды
  → запись с `Источник=photo`, items с estimated amount.

### B2. Исправление

- [ ] После ответа нажать «✏️ Исправить», затем голосом «Курицы было
  300 г»
  → в `Структура_JSON` изменился только item курицы,
  totals пересчитаны, ответ обновлён.

- [ ] Без кнопки: «Исправь последнюю: курицы было 300 г»
  → тот же результат.

- [ ] Проверить сценарий с scale-to-zero:
  нажать «Исправить», подождать 5+ минут (контейнер уснёт),
  отправить «Курицы было 300 г» → исправление применено.

### B3. Undo

- [ ] Добавить еду → «Отмени» → запись удалена.
- [ ] Удалить запись → «Верни обратно» → запись восстановлена
  с тем же UUID.
- [ ] Изменить настройки → «Отмени» → предыдущие значения.
- [ ] Повторный Undo того же действия не срабатывает (idempotency).

### B4. Шаблоны

- [ ] «Запомни последний ужин как стандартный ужин» → запись
  в «Шаблоны» с `Структура_JSON`.
- [ ] «Съел стандартный ужин» → запись создана из шаблона,
  Gemini не вызывался (проверить лог).
- [ ] «Съел половину стандартного ужина» → `portion_multiplier=0.5`,
  totals вдвое меньше.

### B5. Рецепты

- [ ] «Приготовил 600 г курицы, 300 г чечевицы и 20 г масла.
  Получилось 4 порции» → запись в «Рецепты», в «Дневник»
  НЕ добавлено.
- [ ] «Съел полторы порции» → запись в «Дневник» с
  `portion_multiplier=1.5` от `Ккал_на_порцию`.

### B6. Повтор еды

- [ ] «Повтори последний приём пищи» → новая запись, новый UUID,
  новое время, та же структура, `repeated_from_record_id` заполнен.
- [ ] «Съел то же, что вчера вечером» → находит historical запись
  за вчерашний вечер, клонирует.

### B7. Сегодня и advice

- [ ] `/today` → список записей за пищевые сутки, итог,
  остаток до цели.
- [ ] Проверить в 03:00: запись от 23:00 вчера и запись от 02:00
  сегодня попадают в **один** пищевой день.
- [ ] Проверить в 05:00: запись от 03:00 попадает в предыдущий день.
- [ ] `/advice` → короткая рекомендация (не статья).

### B8. Настройки

- [ ] «Поставь цель 1800 калорий» → запись в «Настройки».
- [ ] `/settings` → показывает обновлённое значение.
- [ ] «Отмени» → возврат к 1900.

## F. Устойчивость

- [ ] **F1.** Groq недоступен → пользователь получает короткое
  «Не смог распознать голос, попробуй текстом», сервис не падает.
- [ ] **F2.** Gemini вернул malformed JSON → ограниченный retry,
  затем ошибка в лог, пользователю короткое сообщение.
  Запись в «Дневник» не создаётся.
- [ ] **F3.** Sheets API вернул 500 → retry, при неудаче — короткое
  сообщение, `update_id` не помечен обработанным (при повторе
  Telegram попробует снова).
- [ ] **F4.** Фото битое или слишком большое → короткая ошибка.
- [ ] **F5.** Временные файлы в `/tmp` удаляются.
  Evidence: `grep -rn "tempfile\|/tmp" bot/` → все в try/finally
  или context manager.

## I. Что НЕ входит в MVP

Эти пункты можно не закрывать на первой итерации, но зафиксировать
как known gaps:

- Автоматические отчёты с красивым форматированием (можно текстом).
- Фото + caption с приоритетом текста над визуальной оценкой.
- Сложные модификации шаблонов («стандартный ужин, но курицы 300 г»).
- Повтор с изменением («съел вчерашний ужин, только курицы 300 г»).
- Замена ингредиента в записи.
- Многошаговые диалоги (уточняющие вопросы при низкой confidence).

---

## Как использовать

1. MVP считается готовым, когда закрыты **A + B + C + D + F1-F3**.
2. Production-ready — когда закрыты **все секции A–H**.
3. Пункты из I — отдельной итерацией после первой production-недели.

После каждого изменения кода — прогонять **секцию A** заново.
Она ловит дрейф инвариантов, который случается после любого
рефакторинга.
